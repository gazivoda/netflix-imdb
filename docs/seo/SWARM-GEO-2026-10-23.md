# Rating Watch: GEO visibility, discovery and growth evidence

Audit date: 2026-10-23. Site: https://rating.watch. Business: independent consumer browser extension with an experimental camera tool and research content. This report covers live crawl access, machine-readable summaries, platform requirements, a bounded brand-mention search and comparisons with earlier audits. It complements the technical and content swarm reports.

## Findings and implementation

The public site already permits the major search crawlers and serves useful text without requiring client JavaScript. Changing crawler names or adding speculative AI markup is therefore a low priority. The concrete discovery gap was in `lib/llms.ts`: it hid the 100-film dataset until an individual film analysis was published and never linked the existing 44-film research snapshot. Both datasets are already public, linked from their source pages and useful for checking the site's original analysis.

Implemented: both `/llms.txt` and `/llms-full.txt` now link each JSON dataset when its source page is in the public registry. A ready `/blog` can expose its dataset before any article is published. An unavailable hub does not expose its dataset; unpublished article URLs remain excluded. This improves the completeness of summaries for tools that choose to read them. It is not a promised Google ranking factor or evidence that an AI service will consume these files.

Verification: three regression tests failed against the previous behavior, then **22 llms tests passed** after the change. Fixtures cover a ready hub with zero published articles, a research-only registry, an unavailable hub and a registry with neither source page.

## Live observations

These endpoints were fetched with Python's standard HTTP client, 30-second timeout, sequential requests and at least one second between requests. The web research tool could not open the site's text endpoints; the direct HTTP checks succeeded. Responses were observed before this branch was deployed.

- `/robots.txt`: HTTP 200, plain text, 570 characters. Every explicit crawler group allows `/` and disallows `/api/`.
- `/sitemap.xml`: HTTP 200, XML, 2,742 characters.
- `/llms.txt`: HTTP 200, UTF-8 plain text, 4,823 characters. Consistent Rating Watch name, official store link, accurate IMDb/Rotten Tomatoes distinction and shared OMDb allowance caveat. No dataset download links.
- `/llms-full.txt`: HTTP 200, UTF-8 plain text, 9,942 characters. No dataset download links.
- `/`: HTTP 200, server-rendered title, H1, `index, follow`, no `X-Robots-Tag`. Text includes product definition, questions and explanatory content.
- `/about`: HTTP 200, server-rendered title and H1, `index, follow`, no `X-Robots-Tag`. Person, WebSite and Organization data are present.
- `/blog`: HTTP 200, HTML, 114,182 bytes.
- `/data/netflix-top-100.json`: HTTP 200, JSON, 160,336 bytes.
- `/data/imdb-rt-gap.json`: HTTP 200, JSON, 17,244 bytes.

Live AR pricing reflects its production build settings. The local source uses a billing flag for its own build. This audit does not infer a production billing error from local development settings.

## Crawler access and corrected operator meanings

- Googlebot, Bingbot and Applebot: explicitly allowed to public pages.
- OAI-SearchBot: explicitly allowed. OpenAI identifies it as the crawler used for ChatGPT search results. GPTBot is a separate training control; allowing one is independent of the other. ChatGPT-User serves user-initiated requests. [OpenAI crawler documentation](https://developers.openai.com/api/docs/bots).
- Claude-SearchBot and Claude-User: explicitly allowed. Anthropic identifies these as search indexing and user-directed fetching respectively; ClaudeBot is for training collection. [Anthropic crawler documentation](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler).
- PerplexityBot and Perplexity-User: explicitly allowed. PerplexityBot supports search discovery and is not a foundation-model training crawler; the user agent serves user-directed requests. [Perplexity crawler documentation](https://docs.perplexity.ai/docs/resources/perplexity-crawlers).
- GPTBot, ClaudeBot, CCBot, Google-Extended, Applebot-Extended, Bytespider and cohere-ai: explicitly allowed under the existing site policy. GoogleOther, Amazonbot and FacebookBot inherit the wildcard public access rule. No change in training policy was needed for this work.

The geo-crawlers skill's configuration checklist gives **100/100**: 50 for its five named first-tier agents being allowed, 25 for five second-tier agents being allowed explicitly or by wildcard, 15 for no blanket block and 10 for accessible llms/sitemap files. This is a **configuration checklist score**, not a crawl-success guarantee, citation probability, ranking metric or overall GEO score. Server logs were not available to verify real bot visits or WAF treatment of their published IP ranges.

Several older skill examples incorrectly describe GPTBot as required for ChatGPT search and ClaudeBot as required for Claude search, or refer to Codex as an Anthropic product. Current operator documentation takes precedence over those examples. No recommendation relies on their unsourced traffic percentages or citation-share statistics.

## Platform assessment

**Google AI Overviews and AI Mode:** the same SEO fundamentals apply: indexable public text, descriptive internal links, useful content and structured data matching visible content. Google states that no additional AI text file or special schema is required. Search Console is needed to assess indexing and performance; its Web performance report includes AI-feature traffic. No verified access to that property was available. [Google's AI features guidance](https://developers.google.com/search/docs/appearance/ai-features).

**ChatGPT search:** public crawl access is configured for OAI-SearchBot. Maintain factual descriptions, the real store listing and attributable research. Whether any page is indexed or cited remains unmeasured. Do not assume Wikipedia or Wikidata is a prerequisite.

**Perplexity:** crawl access is configured and the research has downloadable source data. The next useful work is to make findings clear, reproducible and linked from relevant guides. No live citation frequency was measured.

**Gemini:** the product's accurate identity, visible sources, video and publicly readable research are useful foundations. No special Gemini inclusion score or citation result was measured.

**Bing Copilot:** verify the real Bing Webmaster Tools property, sitemap and indexing after deployment. Existing IndexNow tooling can notify supported engines of changed URLs, but a notification is not proof of indexing. Owner credentials and index-coverage exports were unavailable.

No numerical per-platform or composite GEO score is reported: the skill rubrics mix visible configuration with unavailable rankings, account state and third-party authority. Treating unknowns as zero would imply an unsupported failure; treating them as full marks would imply unsupported success.

## Brand mentions: bounded evidence

Searches included `"rating.watch" "Rating Watch"`, `"Rating Watch" Netflix IMDb Rotten Tomatoes`, the exact Chrome Web Store ID with the brand name, and brand/domain queries restricted to YouTube, Reddit and LinkedIn. The returned sample did not identify a relevant independent mention of this project. Results were dominated by unrelated financial "Rating Watch" terminology and unrelated Netflix discussions.

This is a discoverability warning, **not proof of zero mentions or exclusion from an index**. Search recall, geography and result selection are unknown. No backlink database, platform-native analytics, Search Console, Bing Webmaster Tools or traffic export was available. Sentiment, mention counts and audience size are therefore unmeasured. The live official Chrome Web Store URL is linked from the site; that is an identity asset, not an independent editorial endorsement.

Priorities: a real product demonstration with explanatory captions; accurate product information on profiles the owner actually uses; and research that a relevant publication can independently check. Public posts, directory submissions and outreach were not sent. Any future community contribution should follow current community rules and disclose authorship.

## Measurement and 30-day actions

1. After deployment, verify the changed source pages and both text endpoints, then submit the sitemap through the existing verified search-engine properties. Check real URL inspection rather than relying on `site:` queries.
2. Capture a 28-day baseline for organic clicks, impressions, queries, landing pages and the official-store outbound click event. Split branded queries from nonbranded topics such as Netflix match scores, IMDb ratings on Netflix and critic/audience gaps.
3. Review impressions after two weeks to refine page titles and internal anchors around actual queries. Use click-through rates with comparable positions; do not interpret a few impressions as a trend.
4. At 28 days, compare the same windows for organic landing visits, store clicks and conversions. Record seasonality and deployment dates. Group AI referrals by identifiable referrer only; missing referrers remain unknown.
5. Test the same five to ten task-oriented prompts monthly on each AI search product, record date, region, exact query, cited URLs and response screenshots. Report sample results, not universal inclusion claims.
