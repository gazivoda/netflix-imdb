### Low
**L1. Text extraction drops the release date on /about.** The raw HTML is correct: `first public release was on <time dateTime="2026-05-01">May 1, 2026</time>` (`app/about/page.tsx:114`). But trafilatura's text output reads "The first public release was on ." An answer engine that uses a similar extractor would lose the date. Optional fix: put the date in plain text next to the element, or add it to the "Maker credit" list as a plain-text "First release: May 1, 2026" value. (The list label already exists, but it was empty in the extracted text.)

**L2. /pricing does not mention the 3-day free trial in its server-rendered text.** The home page and llms.txt both say "3-day free trial". The no-JS text of /pricing (73 words, ending "Checking your account...") does not mention it. An assistant answering "does Rating Watch Pro have a free trial?" from /pricing alone would miss it. Fix: add the trial line to the static Pro card.

**L3. The page date changes on every deploy.** `render_page.py` reports `publication_date` 2026-11-09 for /, /install, /pricing and both new and older how-to guides. Round 2 recorded 2026-10-23 for the same guide pages. The date the site exposes is therefore a deploy or modified date, not the publish date. Answer engines cannot tell a new page from a redeployed one. Fix: keep `datePublished` fixed per page, and move only `dateModified` when the content really changes. Check what `lib/seo.ts` emits.

### 4a. Chrome Web Store detailed description (3 paragraphs)

What changed from `CWS-LISTING.md` section 3:
- "every title card" is now qualified.
- The privacy line now names the API key.
- Pro is explained.
- The support email is now hello@rating.watch.

```
Rating Watch adds a small badge to the top-right corner of Netflix title cards on netflix.com, showing the IMDb rating (out of 10) and, where OMDb has one, the Rotten Tomatoes critic score (a percentage). Films usually have both; TV series usually show IMDb only, and a title with neither gets no badge. New rows, search results and "More Like This" suggestions are rated as they load. Works in desktop Chrome, Edge and Brave.

No account is needed. Lookups start on a shared OMDb allowance of 1,000 a day across all users, so on busy days ratings can pause and the toolbar icon shows a red "!"; add a free personal OMDb key in the extension options to get your own allowance. Scores are cached on your device for up to 7 days. Titles are matched by name, so a few remakes or same-name titles can show the wrong score.

Privacy: only two site permissions, www.netflix.com and www.omdbapi.com. To look up a rating, the extension sends the card's title text and an OMDb API key (the shared one, or yours) to omdbapi.com, which also sees your IP address. No analytics, no tracking, and it does not read your Netflix account, watch history or cookies. The extension is free; an optional paid Pro AR mode for TVs is described at https://rating.watch/pricing. Privacy policy: https://rating.watch/privacy. Support: hello@rating.watch. Independent project, not affiliated with Netflix, IMDb or Rotten Tomatoes; ratings data from the OMDb API.
```

Basis for each claim:
- **[V] in the extension code:** the badge's position and behaviour (`content.js`); the 1,000-a-day limit, the red "!", the 7-day cache and the key sent with each request (`background.js`); the two host permissions (`manifest.json`); matching by title text.
- **[V] on the site:** the wording "Films usually have both; TV series usually show IMDb only" (/install); "OMDb also sees your IP" (/privacy).
- **[V] by code reading only:** "does not read your Netflix account, watch history or cookies". There is no `cookies`, `history` or `tabs` permission, and the content script reads only `a[aria-label]`. This was not tested at runtime.
- **[OWNER]:** whether to name Pro in the extension listing. It is recommended, because the store already shows "Offers in-app purchases".
